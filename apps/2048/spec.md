# 2048 게임 — 설계 문서 (Plan)

## 개요

방향키(↑↓←→) 또는 모바일 스와이프로 4×4 그리드 위의 숫자 타일을 한 방향으로
밀어, 같은 숫자의 타일이 만나면 합쳐지는 표준 2048 퍼즐 게임이다. 매 이동마다
빈 칸 중 하나에 새 타일(2 또는 4)이 생성되며, 병합으로 누적 점수가 오르는
점수판을 함께 제공한다. `apps/2048/` 안에서 완전히 자체 완결되며, 블로그 빌드
파이프라인(`src/`, `posts/`, `dist/`)과는 무관하게 정적 파일 그대로 열거나
서빙해서 동작한다.

프레임워크 없음, 런타임 의존성 없음 원칙을 그대로 따른다. 순수 HTML/CSS/
바닐라 JS만으로 구현한다.

## 파일 구조

```
apps/2048/
  index.html   # 문서 구조: 헤더(제목 + 점수판), 4×4 보드 컨테이너, 안내 문구, 다시 시작 버튼
  style.css    # 전체 스타일 — 색 토큰, 레이아웃, 타일 색상, 애니메이션, 다크모드, 반응형
  script.js    # 게임 로직 — 상태 관리, 입력 처리, 밀기/병합 알고리즘, 렌더링, localStorage
```

세 파일 외에 추가 자산(이미지, 폰트 등)은 두지 않는다. 아이콘류가 필요하면
텍스트나 CSS로 해결한다.

## 게임 로직 설계

### 보드 상태 표현

- `board`: 4×4 2차원 배열(`number[4][4]`), 빈 칸은 `0`. 값은 실제 타일 숫자
  (2, 4, 8, …)를 그대로 저장한다.
- 전역(모듈 스코프) 상태로 `board`, `score`, `best`, `gameOver`, `won`,
  `keepPlayingAfterWin` 정도를 둔다. 별도의 상태 관리 라이브러리는 쓰지 않는다.
- 렌더링은 상태를 DOM에 1:1 반영하는 단순한 `render()` 함수로 처리한다 —
  가상 DOM/diffing 없이 매 턴마다 타일 엘리먼트를 다시 그린다.

### 입력 처리 및 밀기/병합 알고리즘

- `keydown` 이벤트에서 방향키(`ArrowUp/Down/Left/Right`) 4종만 처리하고
  `event.preventDefault()`로 페이지 스크롤을 막는다.
- 네 방향 모두 **"왼쪽으로 밀기" 한 가지 핵심 함수**로 통일해서 구현한다:
  방향에 따라 보드를 회전/전치(transpose)한 뒤 왼쪽 밀기를 적용하고, 결과를
  다시 역회전해서 되돌리는 방식. 이렇게 하면 4방향 각각 별도 로직을 만들
  필요가 없다.
- 한 줄(row) 밀기 알고리즘:
  1. `0`이 아닌 값들만 순서를 유지한 채 추출한다.
  2. 왼쪽부터 순회하며 인접한 두 값이 같고, **아직 이번 턴에 병합되지
     않은 타일**이면 합쳐서 `값*2`로 만들고 점수에 가산한다. 병합된
     결과 타일은 같은 턴에 다시 병합 대상이 되지 않는다 (표준 규칙 —
     예: `2 2 2 2` → `4 4`, `4 4`가 아니라 한 턴에 한 번씩만 병합).
  3. 병합 후 남은 빈 자리를 오른쪽(밀리는 반대쪽)에 `0`으로 채워 4칸을
     맞춘다.
- 이동 전/후 보드를 비교해 변화가 없으면 "유효하지 않은 이동"으로 간주하고
  새 타일을 생성하지 않는다 (같은 방향으로 더 밀 수 없을 때 턴 낭비 방지).
- 애니메이션을 위해 이동/병합된 타일의 이전 위치·이후 위치 정보를 함께
  계산해 `render()`에 전달하는 것을 고려하되, 최소 구현에서는 "타일 값이
  바뀌는 즉시 다시 그리기" 수준으로 충분하다 (UI/디자인 섹션의 애니메이션
  방식 참고).

### 새 타일 생성 규칙

- 이동이 실제로 보드를 변화시켰을 때만 새 타일을 하나 생성한다.
- 빈 칸(`0`) 좌표를 모두 수집한 뒤 `Math.random()`으로 균등하게 하나를
  고른다.
- 값은 90% 확률로 `2`, 10% 확률로 `4` (표준 2048 확률).

### 점수 계산 규칙

- 두 타일이 합쳐질 때마다 **합쳐진 결과 값**(예: `2+2 → 4`이면 `4`)을
  현재 점수에 더한다. 한 턴에 여러 쌍이 합쳐지면 모두 누적한다.
- 최고 점수(`best`)는 현재 점수가 갱신될 때마다 비교해서 더 크면 교체하고
  즉시 `localStorage`에 저장한다.

### 게임 종료 및 승리 조건

- **패배(게임 오버)**: 보드에 빈 칸이 없고, 네 방향 중 어느 쪽으로 밀어도
  보드가 변하지 않는 상태(= 인접한 동일 값 쌍이 하나도 없음). 매 이동
  후 이 조건을 검사해 만족하면 게임 오버 오버레이를 표시하고 입력을
  막는다.
- **승리**: 보드에 `2048` 타일이 처음 등장하는 순간 승리 배너를 띄운다.
  이때 게임을 즉시 끝내지 않고 **"계속하기" 버튼**을 제공해 사용자가
  선택하면 `keepPlayingAfterWin = true`로 전환해 2048 이후에도 계속
  플레이할 수 있게 한다 (승리 배너는 이후 다시 뜨지 않음). "새 게임"
  버튼도 함께 제공한다.
- "다시 시작" 버튼은 상시 노출하여 언제든 상태를 초기화(보드 리셋, 점수
  0, `gameOver`/`won` 플래그 초기화)할 수 있게 한다.

## UI/디자인

- 레이아웃: 세로 스택 — 제목, 점수판(현재 점수 + 최고 점수 나란히), 보드,
  안내 문구(조작법), 다시 시작 버튼. 보드는 정사각형을 유지하며 화면 폭에
  맞춰 축소되도록 `aspect-ratio: 1 / 1`과 `max-width` + `clamp()` 조합으로
  크기를 잡는다.
- 타일 색상: 숫자 값별로 배경색 단계를 구분한다 (2, 4는 옅은 톤, 값이
  커질수록 진해지는 방식). 색상은 CSS 변수(`--tile-2`, `--tile-4`, …,
  `--tile-2048`, 그리고 8192 이상을 위한 `--tile-super` 폴백)로 정의해
  다크모드에서 토큰만 재정의하면 되도록 한다. 숫자 텍스트 색도 타일
  배경 대비 4.5:1 이상을 유지하도록 값마다(연한 배경엔 어두운 글자,
  진한 배경엔 밝은 글자) 규칙을 둔다.
- 애니메이션: 타일 등장/이동/병합 시 `transform`과 `opacity` 기반의 짧은
  트랜지션(150ms 내외)만 사용한다. `prefers-reduced-motion: reduce`
  미디어 쿼리에서는 모든 트랜지션·애니메이션을 `none`으로 끄고 즉시
  상태만 반영한다.
- 다크모드: 블로그 본문과 동일한 토큰 재정의 패턴을 앱 폴더 안에서
  독립적으로 따른다 — `:root`에 라이트 토큰 정의, `:root[data-theme="dark"]`
  와 `@media (prefers-color-scheme: dark) { :root:not([data-theme="light"]) }`
  두 군데에서 다크 토큰을 재정의. 앱은 블로그와 별도로 배포될 수 있으므로
  블로그의 CSS 변수를 import하지 않고 `apps/2048/style.css` 안에 자체
  토큰 세트(`--bg`, `--text`, `--board-bg`, `--tile-*` 등)를 새로 정의한다.
  토글 버튼(`<button aria-label="...">`)을 헤더에 두고, 상태 3가지
  (라이트/다크/시스템 따름)를 `localStorage`에 저장하며, FOUC 방지를
  위해 `<head>` 인라인 스크립트에서 `data-theme`를 CSS 로드 전에 지정한다
  (블로그 `theme.js` 패턴과 동일한 접근, 코드는 이번 앱 안에서 독립적으로
  둔다).

## 점수판

- 헤더 영역에 "SCORE"와 "BEST" 두 개의 박스를 나란히 배치한다. 현재
  점수는 매 병합 직후 갱신, 최고 점수는 현재 점수가 이를 넘어설 때만
  갱신된다.
- 최고 점수는 `localStorage`(`key: "2048-best-score"` 형태)에 저장해
  브라우저를 새로고침하거나 다시 방문해도 유지되게 한다 — 서버나 계정이
  없는 정적 앱이므로 영속성을 얻는 유일한 수단이며, 2048 게임의 통상적인
  기대 동작이기도 하다.
- 점수 병합 애니메이션(예: "+4" 팝업)은 선택 사항으로 남겨두고 최소
  구현에서는 숫자만 즉시 갱신해도 무방하다.

## 입력 방식

- **키보드(필수)**: `ArrowUp/Down/Left/Right` 4개 키. 포커스가 보드 바깥
  (예: 버튼)에 있어도 전역 `keydown` 리스너로 동작하게 한다.
- **터치 스와이프(모바일 대응, 필수)**: 보드 영역에 `touchstart`/`touchend`
  좌표 차이를 계산해 상하좌우 스와이프를 판별하는 경량 로직을 `script.js`
  안에 직접 구현한다 (라이브러리 없이 순수 터치 이벤트로 충분). 스와이프
  판정 임계값(예: 20~30px 이상 이동)을 두어 탭과 구분한다.
- 화면 하단에 방향 버튼(온스크린 D-pad)을 둘지는 비범위로 남기고, 필요성은
  구현 단계에서 재검토한다 (기본은 미포함 — 스와이프로 충분하다고 판단).

## 접근성/반응형

- 시맨틱 태그: `<main>`, `<header>`, 점수판은 `<div>` + 적절한
  `aria-label`(또는 `role="status"` + `aria-live="polite"`로 점수 변경을
  스크린리더에 알림), 보드는 `<div role="grid">`/타일은 `role="gridcell"`
  또는 최소한 타일 값이 텍스트로 노출되도록 한다.
- 포커스 링 제거 금지. 다시 시작/계속하기/테마 토글 버튼은 `:focus-visible`
  스타일을 갖는다.
- 터치 타깃: 버튼류는 최소 44×44px 확보.
- 뷰포트 375px 기준: 보드가 화면 폭 안에 들어오고 `body`에 가로 스크롤이
  생기지 않아야 한다. `viewport` 메타 태그에 `user-scalable`을 막지
  않는다(핀치 줌 허용 유지, 확대/축소 접근성 존중).
- 게임 오버/승리 오버레이는 보드 위에 뜨는 모달성 UI이므로 키보드로
  다시 시작 버튼에 접근 가능해야 하고, 표시 시 스크린리더가 상태를
  인지할 수 있도록 `aria-live` 영역이나 `role="alert"`를 고려한다.

## 외부 의존성

없음. CDN을 포함한 어떤 외부 요청도 사용하지 않는다. 폰트는 시스템 폰트
스택을 사용하고, 아이콘은 텍스트/유니코드 문자 또는 순수 CSS로 대체한다.
2048 로직 자체가 단순한 배열 연산이라 라이브러리가 필요하지 않다는 판단.

## 비범위 (out of scope)

- 실행취소(undo) / 이동 히스토리 기능.
- 4×4 이외의 보드 크기 선택(3×3, 5×5 등) 및 난이도 옵션.
- 온스크린 방향 버튼(D-pad) — 위 "입력 방식"에서 언급한 대로 1차 구현에는
  포함하지 않는다.
- 서버 저장·랭킹·계정 연동 (최고 점수는 로컬 브라우저에만 저장).
- 사운드 이펙트.
- 타일 색상 테마 커스터마이징(사용자가 색을 고르는 기능).
- 다국어(i18n) — 화면 텍스트는 한국어 기준으로 고정.
- PWA화(오프라인 캐싱, 홈 화면 추가 매니페스트 등).

이 목록에 없는 항목이 리뷰 단계에서 새로 요구되면 별도 논의 후 spec을
갱신한다.
