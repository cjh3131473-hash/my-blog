클로드 코드로 이 블로그를 만들면서, 웹 페이지 하나가 세 가지 언어로 나뉘어 있는 이유를
비로소 이해했다. 셋은 각자 다른 질문에 답한다.

- **HTML** — 여기 무엇이 있는가
- **CSS** — 그것이 어떻게 보이는가
- **JavaScript** — 그것이 어떻게 변하는가

## HTML: 무엇이 있는가

HTML은 내용에 이름표를 붙이는 일이다. 글자를 크게 만드는 게 아니라
"이건 제목이다"라고 말하는 것이다.

```html
<article>
  <h1>오늘 배운 것</h1>
  <time datetime="2026-08-25">2026년 8월 25일</time>
  <p>본문…</p>
</article>
```

`<div>` 로만 채워도 화면에는 똑같이 보인다. 하지만 `<time datetime="...">` 이라고 적어 두면
사람이 아닌 것들 — 검색엔진, 화면 낭독기 — 도 그게 날짜라는 걸 안다.
**보이는 모습이 아니라 의미를 적는다**는 게 핵심이었다.

## CSS: 어떻게 보이는가

CSS는 그 이름표에 생김새를 입힌다. 재미있는 건, 색을 직접 적지 않는 게 더 낫다는 점이었다.
색에 **이름**을 붙여 두면 다크 모드가 거의 공짜로 따라온다.

```css
:root {
  --bg: #fdfdfc;
  --text: #1a1a18;
}

body {
  background: var(--bg);
  color: var(--text);
}
```

다크 모드를 만들 때 `body` 규칙은 손대지 않는다. 이름표의 값만 갈아 끼우면 된다.

```css
:root[data-theme='dark'] {
  --bg: #161614;
  --text: #e8e8e3;
}
```

처음엔 다크 모드용 규칙을 따로 쓸 뻔했다. 그러면 색을 바꿀 때마다 두 군데를 고쳐야 하고,
언젠가 한쪽을 빠뜨리게 된다. 실제로 이 블로그를 만들다가 한 번 빠뜨렸다.

## JavaScript: 어떻게 변하는가

JavaScript는 사용자가 무언가 했을 때 상태를 바꾼다. 테마 버튼이 하는 일은
생각보다 훨씬 적었다 — 색을 칠하지 않는다. **어떤 이름표를 붙일지만 정한다.**

```js
button.addEventListener('click', function () {
  document.documentElement.dataset.theme = 'dark';
});
```

색을 고르는 건 여전히 CSS의 몫이다. JS는 `data-theme="dark"` 라는 표시만 남기고 빠진다.
어떤 아이콘을 보여줄지도 CSS가 정한다.

```css
:root[data-theme='dark'] .icon-moon {
  display: block;
}
```

## 나눠 놓으니 좋았던 점

셋의 경계를 지키면 **하나가 없어도 나머지가 버틴다.**

JavaScript를 꺼 보았다. 테마 버튼은 사라졌지만 글은 그대로 읽혔다.
내용은 HTML에 이미 다 들어 있고, 생김새는 CSS가 이미 다 정했기 때문이다.
만약 글 내용을 JS로 그렸다면 빈 화면만 남았을 것이다.

| | 맡은 일 | 없으면 |
| --- | --- | --- |
| HTML | 내용과 의미 | 아무것도 없다 |
| CSS | 배치와 색 | 못생겼지만 읽힌다 |
| JavaScript | 상태 변화 | 토글만 안 된다 |

아래로 갈수록 없어도 견딜 만해진다. 이 순서를 지키는 걸 점진적 향상이라고 부른다는 것도
오늘 알았다.
